The Game of Backgammon

Backgammon is a popular and complex board game. Playing it requires an intriguing combination of skill and luck. The game is ancient. Its essentially modern form first arose in Persia during the 6th century CE. On the other hand, its most recent innovation, the doubling cube, was introduced in the 1920s. However, its origins date back some 5,000 years.

Using the software described here you can:

  1. Play the game against another human being via the web. The two of you may reside on different continents!
  2. Play the game against any of nine built-in AI brains.
  3. Set up and analyze any position.
  4. Design your own AI and evolve it via a genetic algorithm.
  5. Run a tournament among AIs you design or choose from the existing list.

The Game Board

In the default view of the game board, as shown in Figure 1, the home board of White is in the lower right quadrant, and White's outer board is in the lower left. Similarly, Red's home and outer boards are on the top, on the right and left, respectively. Red moves from the white home board to the red home board and White moves in the opposite direction. Both players move from their opponent's home board to their own home board, and from there to the collection tray next to the home boards. Red moves clockwise, and White moves counterclockwise. The bar contains any checkers that have been forced off the board by the opponent, and the collection tray receives all checkers that have been born off. The points of the board are numbered from 1 to 24. It is sometimes convenient to think of the bar as point 25 for White and 0 for red, and the collection tray as point 0 for White and 25 for Red. With these conventions, Red always moves from some point to a point with a larger index, and White moves to a point with a smaller index. The default view is Red's view as it would be on a physical board. That view is consistent with the diagrams shown in this external Backgammon rules page. You can change the view of the board, as described below.

There are several ways to move a checker from point x to point y on the game board. You can drag it from x to y or you can first click on x and then on y. There is also a setting (see the description of row 18) that let's you move a checker with a single click if that click uniquely identifies the move.

If the move is part of a game the system will let you only make legal moves. However, there is also an examination mode that let's you move checkers freely and set up any position.

1Title and Parallel Processing

This line contains the name of the game, BACKGAMMON, and the current version number. Together they constitute a clickable link that takes you to this manual page.

Workers are individual processes that your computer lets you run in parallel. The software obtains the available number of workers from your computer and by default uses that number of workers to run tournaments and evolutions, or individual games against AIs that search more than one move ahead. You can replace the default number by any other positive integer. Using fewer workers than are available may slow down your computations, but it may be advantageous when you re running other CPU intensive processes on your system. Specifying more than the available number of workers is possible, but not likely to be useful. Many computers offer 8 processes, but you may have many more.

3 Playing Over the Network

These controls let you set up a match between two human players in two different locations. Both of you have to have an internet connection, and you also have to have an open communication channel to your opponent, by telephone, on screen, or by email. One of you serves as the host, the other as the guest. To set up a match proceed as follows:

  1. As host click on the button labeled HOST. A code (usually a three digit integer) will appear in the text field labeled CODE. Communicate that code to the guest.
  2. As guest enter the code into your CODE text field, by clicking on the word CODE and typing the code for your game session. The word CODE will disappear in the process. Establish the connection by pressing the enter key, or by clicking on the button labeled JOIN. Once the connection is established a notification will appear in Line 4.
  3. As host click on Start (in row 5) and then click on the playing dice in row 9 to determine who starts the game. If you have already played a game, and you want to play another, as host click on RESTART in row 5.
  4. The two of you can then play a game as described below.
  5. The LEAVE button severs the network connection. It does not reload the page or reset the board; it simply disconnects you from your opponent. Either player can leave and continue on their own computer.

    6. Notes:

  6. The host always plays as White, the guest as Red. Either player may be the first to roll the dice. In the first game, the first player to roll the dice is determined by random. Thereafter the beginning player alternates.
  7. The Host's view by default is White, that of the guest is Red.
  8. Either of the two players can act as host, but the guest does not have all the privileges that the host has. In particular the guest cannot restart a game, or navigate back and forth within the game (see the description of row 10). The main purpose of this restriction is to remove sources of confusion.

6 7Player Selection

Here you can select the white player in the first menu in that row. The options are either Human (the default) or one of one of nine AI players, ranked by decreasing performance. The cyan text field keeps track of the score in a multi game match. The button labeled Z resets the score field to zero. The depth menu let's you select the search depth for AI players, measured in plies (half moves, the action of one player). 1 ply is the default, and overall by far the most useful setting. At 0 plies the AI picks the first available legal move. You can use this setting if you are looking for a crazy opponent, or for other experiments. 1 ply applies a static evaluation function to every board that can be obtained with a legal move. It then picks the move that yields the best scoring board. This is very fast, for human play against an AI as well as for tournaments or evolutions. 2 plies considers all possible dice rolls and moves after the first ply, and then computes an expected score for the board after the first ply. A two ply search performs only a few percentage points better than a one ply search, due to the random nature of the unknown next roll of the dice, but it requires several seconds for each search. It is a reasonable choice for a human playing against an AI. A 3 ply search goes one ply deeper, but it's utility is severely limited by the large amount of time it takes for the analysis of just one dice roll.

There is a separate page giving more information about the AI players and algorithms.

9Game Mechanics

You use the controls in this row during a game against a human or an AI. Specifically, there are:

  1. The Playing Dice. Initially one of the dice is White, and the other is red. Clicking one them will determine first move, and which player will make it. Otherwise, the color of the dice indicates the player whose turn it is. It alternates between red and white as the game proceeds. When the dice are blank you can click on them to roll them. For example, in Figure 2 it is Red's turn to roll the dice. As you make your moves the dice turn blank. For example, if you roll 5-3 and move one checker 5 spots forward then the die showing the 5 will turn blank and the other die will continue to show 3. Thus the dice always show what kind of moves you can still make. After you make the second move of three spots forward the dice will turn white, and it will be the other player's turn. If you roll a Double both dice will continue to show the pips after your first two partial moves, and then will turn blank one at a time.
  2. The Doubling Cube. You offer a Double by clicking on the Doubling Cube. Your opponent is notified of your offer and can accept it by clicking on the playing dice or reject it and resign by clicking on the doubling cube. The color of the Doubling cube indicates the current owner of the cube. Initially it is gray, indicating that either player may double.
  3. The Undo Button. If you have made a move but you still have moves available you Can undo a move using this button. Thus you can always undo the first move, and when rolling a double you can undo the first three moves. However, after you make the last move of your current toll the game automatically switches to the other player and the undo button is ineffective.
  4. The View Menu. This menu let's you choose the orientation of the game board on your screen. There are five options:
    1. White. White's home board is on the bottom right. This is the view shown in Figure 1, and the view White would have when viewing a physical board.
    2. RedSimilarly, the view Red would have. Red's home board is in the bottom left quadrant.
    3. Home This is one view a spectator could have. The home boards are at the bottom of the screen.
    4. Outer.The view a spectator on the other side of the board would have. The outer boards are at the bottom of the screen.
    5. Magriel. A view that is consistent with the diagrams in Magriel's book, with White corresponding to X and Red corresponding to O. It can be obtained by reflecting the White view across the bar, or the Red view across the horizontal axis.
    The default view is White, except that when playing a networked game the default view of the guest is Red.

10Move List and Game Navigation

This field contains a scrollable list of the moves so far in the current game. It lists the number of each move, the dice roll, and the resulting moves. For AI players, the score is assigned by the AI selected selected as the player, for human players the score is assigned by the AI specified in Row 13.. Showing the score can be turned on and off in the Settings. Positive scores are good for White and are shown in white print in a white font in the Table. Similarly, negative scores are good for Red and are shown in red.

Clicking on any row in the table will take you back to the current move and reset the game board to the configuration after that move. The game can be resumed from that position by clicking on the playing dice. Any dice rolls made earlier will be repeated. Thus the Table can be used to explore alternatives to previous moves. However, you can start from an earlier position with fresh dice rolls by clicking EX in row 12, followed by clicking START in row 5.

12 Examination and Analysis

The controls in this row let you set up a position and analyze it, or start a game from it. You can move checkers on the board , including the bar and the collection tray, by dragging or clicking on start and finish, without restriction. The first three buttons set up an initial configuration. Specifically, EX selects the position currently on the board, e.g., the position in an ongoing game. CL starts a position with all checkers on the bar. IN loads the regular starting position. The red and white menus serve as dice. You can select a roll using either the red dice or the white dice, but not both sets. If you start an analysis or a game, and no dice have been set, the system will apply a random roll. MOV lists available legal moves in the move list field, ranked by the AI selected in Row 13, and PLAY applies that move to the board. The START button in Row 5 starts a game from the currently set up position, and the RESTART button in the same row restarts a game from the same position as the most recent game. You can navigate in a set up game exactly as you would in a regular game. By default, doubling is turned off min examination mode (to prevent immediate terminations in lopsided positions).

Matches

In this context it is important to understand the concept of a match. A match is a set of 1 or more games. If a match consisted of a single game with unlimited doubling it is possible that the point count in that game becomes astronomical by repeated doublings. This has actually happened in earlier versions of this software. One game with millions of points can dominate all other games in a tournament of thousands of games. Therefore a match is defined, in actual competitive pails, and in this software, in a way that prevents dominance by high point games. The players play usually several , using the doubling cube freely, but only until they reach or exceed a specified point count. That point count is set in the menu on row 17. It is 11 by default. So a match can involve up to 11 games, or it could be determined in a single game that involves 20 doubles and that counts for \(2^20 = 1,048,576 points. The winner still only receives 11 points. To avoid certain artifacts of symmetry the value of the match is odd. Available choices are the odd numbers from 1 to 19. Choosing 1 in particular creates matches that consist of a single game, with doubling, gammoning, and backgammoning having no effect on the match outcome.

13Importing and Exporting AIs

The controls in this row let you import or export an AI. You Can thus keep a set of AIs of your own, play against them, evolve them, or let them play a tournament against other AIs. From left to right, the following controls are available:

  1. The AI menu, showing Arwen by default, lets you pick any of the currently active AIs. This will update the parameter list in row 15 and you can then work with that AI. If a game has been played by two humans, or is ongoing, and a move list is present, then changing the selection will also change the AI used for scoring the game positions, and the scores in the moves list will update. By default, 9 AIs are available. They are sorted alphabetically by decreasing performance (as determined by a long tournament). I picked the parameters of the bottom one, Origin, basically by guessing, when I first started developing the software. Quite a few of Origin's parameters are zero (they have no effect) since they did not yet exist when I constructed Origin. The other AIs all were created in one way or other by mutating Origin and its successors, partly by changing individual parameters by hand, or applying the genetic algorithm available in the next row. If you import a new AI it will be added to the bottom of the menu, and it will become eligible in row 16 for playing a tournament.
  2. The textfield let's you specify the name of the currently selected AI for export. The default name is newAI, but you can change it. Your selection will be used as file name, and as the name of the exported AI.
  3. The EXPORT button downloads a .js file that defines the new AI in a JavaScript code. That same file is suitable for importing an AI, and you can edit it.
  4. The IMPORTbutton let's you import a new AI, defined in the same format as any exported AI, adds it to the menu in row 13, selects it in that menu, and updates the parameters in row 15. Clicking on the import button opens your browser's file picker. However, you can also import an AI by dragging the file onto your control column. The system will notify you in the status field whether the import was successful or not.
  5. The DEF button resets the parameters in row 15 to their original values and thereby undoes any changes you may have applied in those textfields.

14AI Evolution

You can simulate an evolution that may create a more effective AI. The algorithm itself is described on the AI page. From left to the right, the controls in this row have the following effects:

  • The EVOLVE button starts the process. Pressing the button again stops the process. Any improved mutant that is found is downloaded immediately.
  • The menu labeled D: with a default of 1 ply can be used to change the depth at which the AI considers each move. However, depths 2 or 3 take much longer than depth 1 which is by far the most practical.
  • he first of the three white text fields let's you specify the maximum numbers of generations that will be explored. However, this choice is not critical since improved mutants will be saved immediately. The default is 1000
  • In the second text field, with a default of 100, you set the number of matches per tournament among the competing mutants.
  • The last text field, with a default of 50, sets the maximum percentage by which any single weight may be mutated at each stage.

      18 Settings and Data Export

      The two menus in this row let you change certain settings and upload some specific information.

      Settings

      The following settings are available:
      1. ANIMATION Default: ON: The move of an AI, or a human opponent in a networked game is animated.
      2. HIGHLIGHT Default: OFF: When clicking on a checker the possible destinations of that checker according to the current dice roll are highlighted.
      3. SHOW SCORE Default: ON Determines whether the moves table in row 10 shows the AI computed scores of the positions after the moves.
      4. SPEAK Default: ON When computer voices are available on your system then Doubles and Game endings are announced audibly (as well as in the status field in row 8). The specific reason for adding this facility is that in a networked game between two humans it is easy to overlook the doubling message in the status field.
      5. Auto Roll Default: OFF When it is a human's turn the dice are rolled automatically which makes it unnecessary to click on the playing dice at every turn. Notice, however, that turning this feature on makes it impossible to double.
      6. AUTO MOVE Default: OFF A single click on a checker will move that checker if the move is unique.
      7. DOUBLING Default: ON Turns Doubling on or off. When OFF humans and AIs are unable to double.
      8. AUTO START Default: OFF When on the initial red and white dice are rolled automatically rather than manually.
      9. STATISTICS Default: OFF. When on, a Tournament or Compete run appends a Statistics section to its results spreadsheet: the escape-roll distribution, and how often the bar-entombment weight actually changed a move. It costs nothing while it is off, but it is expensive while it is on — measured at about 2.4 times the running time at depth 1, because the bar-entombment measurement re-ranks every decision a second time. Leave it off unless you want those two numbers.
        A Throughput block — workers, total games, games per second, milliseconds per game — is written to every results spreadsheet whether or not this setting is on, since counting games and reading a clock costs nothing. Those figures are the way to compare one machine with another, or to measure how well a run scales across cores: repeat the identical run with the Workers field set to 1 and divide. The block records whether the statistics probes were running, because if they were the timings are not those of the engine as it actually plays.
      10. TIME TRAVEL Default: ON Makes it possible to go back to previous moves in the moves table.

      Exporting Data

      The following information can be downloaded:
      1. SCREEN IMAGE You can download an image of the game window, including the control column, to show your friends. When you do, for security reasons your browser has to ask you to confirm that you really want to do this.
      2. BOARD IMAGE Similarly, downloads a screenshot of just the game board.
      3. MOVE LIST Downloads a text file with the move list shown in row 10.
      4. CONSOLE LOG downloads a text file with the transcript of the console log. The console is not used at all for game play, but this option proved extremely useful for debugging during game development.
      5. BOARD VALUE downloads a detailed description of how the current position score is calculated.
      6. MOVE TABLE downloads spreadsheet with a list of what the AI considers the best move for each possible dice roll.
